# Безопасность Milo Home

Не публикуйте в Issues ключи, пароли, токены, личные сетевые сведения и полные дампы устройства. Об уязвимости сообщайте через GitHub private vulnerability reporting, если оно доступно, либо запросите у владельца приватный контакт без публикации деталей эксплуатации.

## Границы доверия

GitHub Releases может сообщить о кандидате, но не разрешает сменить ключ подписи. Клиент проверяет SHA-256 и настоящую криптографическую APK-подпись, package, код, API, ABI и variant. Метаданные и manifest APK должны соответствовать установленному варианту. Standard не получает byedpi, test-track не получает production по случайному совпадению версии.

FileProvider закрыт; только проверенный APK передаётся системному установщику с временным правом чтения. Токены и ключи выпуска не входят в клиент. Нет root, молчаливой установки, Accessibility-автоматизации, отключения пакетов или скрытой смены HOME.

## Проверки и выпуск

Instrumentation может подменить транспорт только внутри своего подписанного тестового процесса; публичного test-endpoint/IPC нет. Публикатор отвергает debuggable APK. CI не получает release-ключи, workflow выпуска запускается вручную из разрешённой ветки. Подписи Stable/RC согласованы; тестовое окружение изолировано.

Backend ByeByeDPI использует signature-permission и проверку пакета/UID/подписи. Его обновление не выполняется обновлятором лаунчера. Любая первоначальная миграция с несовместимым ключом требует отдельного плана; удаление данных не является запасной автоматической операцией.

Сохраняйте независимую резервную копию release-keystore и восстанавливаемого пароля. [Подпись](docs/SIGNING.md) · [Испытания](docs/TESTING.md).
