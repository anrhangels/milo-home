# Milo Home 0.0.9-rc.1 — проверка предварительной версии

Preview прошла испытания на Android TV 11; та же реализация входит в стабильную 0.0.9 с новым versionCode 111. Прирост свободной RAM и снижение CPU в одинаковых условиях пока не измерены.

## Что покрывает изменение

| Запрос | Реализация / граница |
| --- | --- |
| Остановка скрытого интерфейса | Усилена отмена анимаций, отложенного фокуса и минутных задач; прежний onPause уже останавливал фон |
| Каталог без полного перечитывания на Home | TileRefresh уже сохранял список; AppCatalog теперь кэширует запросы и обновляет пакет из broadcast/ChangedPackages |
| Общие изображения | Один ограниченный кэш ConstantState; разные View получают свои оболочки с общей bitmap. Разные иконка и баннер остаются разными ресурсами |
| Отмена загрузки после закрытия | Задания библиотеки отменяются, результаты закрытого окна не применяются |
| Цвет приложения | Общий кэш цвета до обновления пакета, смены темы или завершения процесса |
| Минутные часы | TextClock уже использует минутный формат; задачи сцен выровнены по минуте |
| Общий механизм видимых сцен | MinutePulse обслуживает Home и ClockScene, без подписчиков не планирует работу |
| Выключенный экран | ScreenWork приостанавливает визуальные задачи и возобновляет их после пробуждения |
| Изменения без пересоздания Home | Прозрачность дока, начертание/яркость часов и задержка заставки. Структурные изменения раскладки могут пересоздавать Activity |
| Повторное открытие меню | Ограничены повторные запуски; открытая библиотека/меню не создаются заново при быстром повторном действии |
| Очередь старых нажатий | Отбрасываются устаревшие DOWN навигации; Back, Home, громкость и UP сохраняются |
| Прокрутка библиотеки | Сохраняются выбранный пакет, позиция и смещение |
| Возврат выделения | Сохраняется кнопка/карточка, открывшая меню; сетевое меню уже возвращало фокус к Wi-Fi |
| Позиция настроек | Переключение сохраняет прокрутку и выделение текущего раздела |
| Новые приложения и док | Сохраняется прежний порядок автоматически заполненных мест; ручной порядок имеет приоритет |
| Фильтр по букве | Выбор доступной первой буквы без ввода с клавиатуры |
| Ошибка запуска | Различаются удалённое, отключённое и ограниченное/изменившее запуск приложение |
| Убрать сломанную карточку | Только после подтверждения; само приложение не удаляется |
| Технические приложения | По умолчанию скрываются не добавленные владельцем системные мобильные/служебные пункты; «Показать все» отменяет фильтр. Это эвристика каталога, не отключение пакетов |
| Редактирование дока | Сохраняется существующее живое перемещение; добавлен номер места в заголовке/озвучивании |
| Названия | Локальный псевдоним карточки, до 40 символов; сброс к исходному имени, очистка управляющих знаков |
| Свободное место | Существующая проверка сохранена, сообщение показывает необходимое и доступное место |
| Очистка APK | Существующее удаление установленного/старого APK сохранено; актуальная частичная загрузка не удаляется при проверке |
| Продолжение загрузки | Идентичность версии/хеша/размера, Range и проверка Content-Range. Ответ 200 перезапускает файл, а не дописывает его |
| Статус после закрытия | Частичная загрузка отмечается как прерванная; готовый APK восстанавливается из кэша только после повторной полной проверки |
| Сохранение настроек при обновлении | Автоматическая установка 0.0.8 → 0.0.9-rc.1 на эмуляторе для обоих вариантов, проверка настроек и HOME |

Нативное декодирование уже выполняющегося изображения может завершиться; отменяются ожидающие задания и применение результата. Кэш изображений ограничен 4 МиБ и освобождается при сигнале нехватки памяти. Частичный файл хранится в кэше до семи дней: Android может освободить этот кэш раньше. Возобновление не гарантируется, если сервер не поддерживает нужный диапазон — тогда загрузка начинается заново. Проверки полного SHA-256, подписи, версии, пакета и варианта остаются обязательными.

## Выполненные проверки

- JVM-тесты, lint и обычные сборки обоих вариантов; проверки инструментов релиза и публичного дерева.
- Два реальных сценария обновления APK с сохранением столбцов, прозрачности, анимаций, режима обновлений, часов, собственного имени, состояния библиотеки и прежнего HOME.
- Семь Android-тестов на отдельном эмуляторе Android 11: остановка минутного цикла скрытого/погашенного экрана, применение прозрачности без пересоздания Home, общий bitmap и инвалидирование цвета, закрытие/повторное открытие библиотеки, прерванный поток и отказ от невалидного APK, продолжение настоящего подписанного APK и восстановление READY при новом менеджере.
- В сетевых Android-тестах транспорт заменён локальной контролируемой моделью. Они не подтверждают поддержку Range у любого провайдера или реальную OTA-установку на телевизоре. Тестовая будущая сборка 111 не публикуется и не устанавливается этими тестами.

## Результат испытаний на физическом ТВ

Preview получена через настоящий GitHub Release и установлена поверх 0.0.8. Хеш установленного APK совпал с опубликованным ByeByeDPI-вариантом; постоянная подпись совпала. HOME, состояние отключённых/исключённых системных пакетов, заставка и accessibility-настройки сохранились. Два ранее исключённых фоновых vendor-процесса не появились снова.

Владелец сообщил, что проверил Home, стрелки, OK, Back, удержание громкости, настройки, библиотеку и фильтр по первой букве; проблем не сообщил. Оба опубликованных APK дополнительно проверены по подписи/хешу и настоящему Range-ответу GitHub (206, правильный Content-Range и точные байты).

Стабильная 0.0.9 собирается из этой реализации с новым кодом 111. Самостоятельная установка стабильного номера — следующий шаг после публикации. Это не замена versionName у готового файла RC.

## Порядок испытаний и перехода в Stable

1. Сохранить на физическом ТВ версию, HOME, состояние пакетов, настройки и исходную загрузку CPU/RAM.
2. С согласия владельца установить Preview того же варианта поверх текущего Milo, без удаления данных и без смены подписи.
3. Проверить Home, стрелки, OK, Back, удержание громкости, Wi-Fi/ByeByeDPI, Android settings, библиотеку, фильтры, имена, перемещение, заставку, погашение/пробуждение.
4. Сверить состояние пакетов и HOME, журналы сбоев и ресурсы в одинаковых условиях.
5. Исправления выпустить следующей RC с большим versionCode. После испытаний собрать стабильную 0.0.9 с отдельным большим кодом; не переименовывать RC-файл в Stable.
6. Проверить доставку настоящего стабильного APK через GitHub Releases, скачать опубликованные файлы и повторно проверить подписи и хеши. Итог установки подтверждает владелец на экране Android.

## Воспроизведение автоматических тестов

Для обычных проверок используйте команды из AGENTS.md для standard/byedpi. Для Android-сценариев соберите изолированную test-сборку с `-PmiloInstrumented`, установите APK и androidTest APK на явный serial эмулятора и запустите классы `ResumeDownloadTest`, `OptimizationLifecycleTest`, `OptimizationLibraryTest` через AndroidJUnitRunner.

Полный сценарий готового APK дополнительно требует локальный подписанный byedpi test-APK с versionCode выше тестируемого приложения в каталоге MILO_TEST_ASSETS под именем resume-next.apk и аргумент `-e resumeFixture true`. Эти файлы остаются вне Git. Без явного аргумента этот один сценарий пропускается.

Сценарии обновления настроек находятся в tools/device-tests: `testSeedOptimizationUpgrade` на 0.0.8, установка новой версии поверх, затем `testVerifyOptimizationUpgrade`. Инструментальный APK подписывается тем же локальным тестовым ключом. Такие тестовые сборки не публикуются и не ставятся на рабочий телевизор.

[Концепция простых стилей](../ADDONS-CONCEPT.md) подготовлена отдельно и не означает, что магазин уже реализован.
