# Milo Home 0.1.0 test plan and evidence

Preview 0.1.0-rc.1 / code112, followed by 0.1.0-rc.2 / code113 and 0.1.0-rc.3 / code114. Stable publication follows acceptance, not just compilation.

## Scope

Selective CleanYourTV 3.0 compatibility changes, black/ambient clock background, clock size, a reversible reduce-effects action, and transitions respecting animation preferences. No new system permissions, automatic package disabling, plugin execution, HOME replacement or VPN strategy changes.

## Reproduce

1. Record HOME, version, disabled/user-uninstalled packages, screensaver and accessibility settings; save the installed APK outside Git.
2. Run tests/lint/minified builds for both editions and the Python release checks.
3. On an isolated Android11 emulator test both clock backgrounds, settings persistence and navigation; existing lifecycle/library tests must pass.
4. Publish a permanently signed Preview. Verify actual downloaded APK hash, certificate, identity, version and edition.
5. On the authorized TV update over the existing app. Test Home, quick settings, library and return focus; clock preview, size/background persistence and reduce-effects cancellation/application. Restore original preferences after testing.
6. Check hidden Home and sleep/wake, crash logs, unchanged HOME/package states, VPN state, storage and comparable idle CPU/RAM snapshots.
7. Owner checks physical Home/arrows/OK/Back/held volume. Publish Stable only after acceptance.

## Recovery

The old APK and state record are saved locally. A lower version cannot normally update over the Preview through the Android installer. Prefer a forward recovery build signed with the same permanent key and a higher versionCode; do not uninstall or promise full private-data backup. Keep the same appId and signing certificate. No destructive migration is required.

## Results

Both editions passed 264 JVM tests, Android Lint and optimized release builds. All 17 Python release/tool tests and the public-tree scan passed. Seven Android11 instrumentation tests passed, including external audio-volume events: clock appearance persistence/rendering, hidden/screen-off lifecycle, shared artwork and library focus/cancellation. Minified UI and physical-TV acceptance remain in progress.


## Physical TV, RC1 finding

A genuine permanently signed RC1 was installed over 0.0.9 through authorized ADB replacement, without uninstalling data. The previous app detected RC1 through its real GitHub feed and showed the green update button and RC option. This installation was not a second end-to-end Android-installer OTA test.

Installed APK bytes matched the public asset. HOME,20 disabled packages,two user-excluded vendor packages,screensaver and accessibility settings were unchanged. Clock background/size persisted across settings reopening; native fullscreen preview and reduce-effects cancellation/application passed. Original animation/clock choices were restored.

A real firmware interaction was found: the TV consumes hardware volume keys before Activity.dispatchKeyEvent, so audio changed while the open slider stayed stale. RC2 adds visible-only audio broadcasts that read AudioManager's real state, with no polling or background service. A regression instrumentation test passed. Physical RC2 retest is still pending.

TV remote-helper accessibility services were not enabled; their screen-off guard is not claimed as an active-service test on this TV. Physical remote owner acceptance and Stable publication remain pending.


## RC2 and RC3

The published RC2 installed over RC1 without data removal. Volume synchronization passed on the real TV:40%→41%→40%; original volume restored. Library filtering and protected VPN IPC answered correctly (VPN remained off).

Further TV testing reproduced an Android task reuse issue: after All settings, reopening the quick panel could bring Android settings back instead. External pages now launch in their own task, and the ephemeral panel opens independently of stale tasks left by earlier versions. A second edge case affected returning focus to Wi-Fi after visiting the library; network dismissal now waits for the Home window to regain focus and clears an obsolete library return request.

Both regression tests passed on Android11. Nine instrumentation tests passed together after the sleep test was corrected to drain the shell command and await actual display state rather than closing the command descriptor immediately. The first failed run is retained locally; no product sleep fix was inferred from that test-harness error. RC3 physical-TV retest remains pending.
