# Переход на Milo Home

[Установка](installation/README.md) · [English](SIGNING.en.md) · [Восстановление](ROLLBACK.md)

Инструкция относится к Android TV и Google TV разных производителей. Возможности ADB и выбор домашнего экрана зависят от прошивки. Названия резервного лаунчера нужно получать со своего устройства.

## Выберите сценарий

| Что установлено | Что делать | Данные |
| --- | --- | --- |
| Нет пакета `com.gathin.tvhome` | Обычная [установка](installation/README.md), заводской лаунчер оставьте | Данные других приложений не затрагиваются |
| Этот пакет, подпись совместима | Сценарий A: обновление поверх | Обновление сохраняет данные приложения |
| Нужен другой вариант Standard / ByeByeDPI | Сценарий B: ручная смена варианта | При совместимой подписи — обновление поверх |
| Этот пакет, другой сертификат и нет проверенной цепочки смены ключа | Сценарий C: первоначальная переустановка | Частные данные удаляемого приложения будут потеряны без отдельного рабочего экспорта |

Одинаковое имя приложения не подтверждает совместимость. Хеш SHA-256 файла и SHA-256 сертификата — разные проверки.

## 1. Проверка перед любыми изменениями

Скачайте APK выбранного варианта из [Releases](https://github.com/anrhangels/milo-home/releases), проверьте хеш файла по инструкции для своей ОС. `apksigner` и `aapt` входят в Android SDK Build-Tools, отдельно от Platform-Tools.

```text
apksigner verify --print-certs Milo-Home.apk
aapt dump badging Milo-Home.apk
```

Для ByeByeDPI замените имя файла на `Milo-Home-ByeByeDPI.apk`. У официальных production Stable и RC обоих вариантов сертификат:

`0eb3e4397a0f1f2c05925c47da6bebeea0e757c41967642af051c774d72b36db`

Проверьте `package: name`, `versionCode`, `sdkVersion` и архитектуры APK против устройства. Идентификатор лаунчера — `com.gathin.tvhome`. Не доверяйте новому сертификату только потому, что он указан рядом со скачанным файлом.

В командах ниже замените `SERIAL` на идентификатор из `adb devices -l`. На Windows может требоваться `./adb.exe`, на Linux/macOS — `./adb` или полный путь. Команды этого раздела только читают сведения:

```text
adb devices -l
adb -s SERIAL shell getprop ro.build.version.sdk
adb -s SERIAL shell getprop ro.product.cpu.abilist
adb -s SERIAL shell am get-current-user
adb -s SERIAL shell pm list users
adb -s SERIAL shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
adb -s SERIAL shell pm list packages -d
adb -s SERIAL shell dumpsys package com.gathin.tvhome
adb -s SERIAL shell pm path com.gathin.tvhome
```

Сохраните вывод локально: текущий HOME, пользователя, отключённые пакеты, версию приложения. При `unauthorized` подтвердите запрос отладки на экране устройства. При отсутствии соединения остановитесь.

Если пакет установлен, создайте на компьютере папку `old-apks`. Из вывода `pm path` скопируйте путь после `package:` и сохраните APK:

```text
adb -s SERIAL pull APK_PATH old-apks/base.apk
apksigner verify --print-certs old-apks/base.apk
```

Если путей несколько, сохраните **каждый split APK под отдельным именем**. Сравнивайте полный SHA-256 сертификата через `apksigner`, а не короткое поле `signatures` из системного дампа.

**Копия APK не является копией настроек.** Запишите список/порядок приложений и настройки, сделайте скриншоты. Универсального экспорта настроек Milo Home сейчас нет. Обычный ADB не гарантирует доступ к частным данным release-приложения; `adb backup`, отказ в доступе или скопированный APK не подтверждают резервную копию данных. Не обещайте восстановление без проверенного способа экспорта.

## A. Совместимое обновление

Нужны тот же package, совместимая подпись и больший `versionCode`. Встроенный обновлятор дополнительно сохраняет выбранный вариант. Для ручной установки:

```text
adb -s SERIAL install -r Milo-Home.apk
```

Продолжайте только после `Success`. При `INSTALL_FAILED_UPDATE_INCOMPATIBLE` или `VERSION_DOWNGRADE` остановитесь: не добавляйте `-d` и не удаляйте приложение автоматически. Проверьте подпись и код версии. После установки выполните проверки из последнего раздела.

## B. Смена Standard / ByeByeDPI

Варианты имеют один package и не устанавливаются одновременно. При одинаковом сертификате и коде версии не ниже установленного можно вручную поставить другой вариант с `install -r`. Встроенный обновлятор сам вариант не меняет.

Например, с RC с кодом 103 нельзя обычным обновлением перейти на Stable с кодом 102 — дождитесь Stable с более высоким кодом. Ориентируйтесь на фактические коды, а не только название версии.

Standard не удаляет отдельно установленный ByeByeDPI и не выключает его VPN. Для варианта ByeByeDPI нужен совместимый парный backend. Его APK и сертификат проверяются отдельно; конфликт подписи backend нельзя решать незаметным удалением этого приложения.

## C. Другая подпись: первоначальная переустановка

Если нет проверенной цепочки смены ключа, установка поверх невозможна. Практический путь — сохранить доступные сведения, подготовить рабочий запасной HOME, затем удалить старое приложение и поставить новое. **Удаление стирает частные данные приложения. Разрешение установить APK не означает согласия на их потерю.**

Команды ниже рассчитаны на обычный пользовательский APK и один профиль Android. Для системного/обновлённого системного приложения, shared UID, нескольких профилей или ограничений администратора нужен отдельный разбор: не применяйте наугад `--user 0`, `-k`, root или сброс устройства.

### C1. Сначала подготовьте запасной HOME

Посмотрите доступные домашние экраны:

```text
adb -s SERIAL shell cmd package query-activities --brief -a android.intent.action.MAIN -c android.intent.category.HOME
```

Выберите **другой установленный рабочий лаунчер** в системных настройках. Если прошивка поддерживает команду и изменение отдельно согласовано:

```text
adb -s SERIAL shell cmd package set-home-activity FALLBACK_COMPONENT
```

`FALLBACK_COMPONENT` берётся из вашего устройства. Если команды недоступны, используйте интерфейс производителя. Проверьте физической кнопкой Home, что открывается именно запасной экран, и что ADB остаётся доступен. Помощник переназначения Home тоже не должен возвращать старое приложение.

Если подходящий лаунчер отключён, его включение требует отдельного согласованного изменения; запишите это исключение в списке отключённых пакетов. Если запасного HOME нет, сначала подготовьте доверенный альтернативный лаунчер или предусмотренный производителем способ восстановления. **До успешной проверки запасного экрана ничего не удаляйте.**

### C2. Контрольная точка перед удалением

Должны быть готовы все пункты:

- Новый APK проверен: хеш, package, сертификат, версия, Android и ABI.
- Старый APK и все его splits сохранены; понятен способ повторной установки.
- Запасной HOME работает с пульта, ADB подключён.
- Записаны восстанавливаемые настройки и честно перечислены данные, которые будут потеряны.
- Владелец отдельно подтвердил удаление старого приложения и потерю этих данных.
- Нет неразобранных системных, профильных или административных ограничений.

### C3. Удалите старое и установите новое

**Только после C1–C2**, на согласованном устройстве:

```text
adb -s SERIAL uninstall com.gathin.tvhome
```

После `Success` установите выбранный APK:

```text
adb -s SERIAL install Milo-Home.apk
```

Для ByeByeDPI используйте соответствующий APK и отдельно проверенный backend. При конфликте ключа существующего backend нужен собственный план сохранения/удаления его данных. При любой ошибке остановитесь и оставьте запасной HOME работающим.

### C4. Сначала проверьте приложение, затем назначьте HOME

Откройте Milo Home из списка приложений. Проверьте стрелки, OK, Назад, настройки и Wi-Fi. Восстановите только действительно сохранённые настройки вручную. После успешной проверки выберите Milo Home домашним экраном через настройки устройства; запасной лаунчер оставьте доступным. Подтвердите работу физической кнопкой Home.

### C5. Если новая установка не работает

Сначала вернитесь на проверенный запасной HOME. Если новый пакет не установлен, установите сохранённый старый APK. Если новый уже установлен и его подпись отличается, для возврата потребуется **отдельно согласованное удаление новой установки**, с потерей её данных.

Для одиночного APK:

```text
adb -s SERIAL install old-apks/base.apk
```

Для split-установки используйте `adb install-multiple` с полным сохранённым набором APK. Старая подпись внутри сохранённого APK позволяет переустановку без старого приватного ключа, но **удалённые частные данные этим не возвращаются**. Повторно назначайте старый HOME только после проверки его запуска.

## Проверка результата

Сравните версию, сертификат, вариант, HOME и список отключённых пакетов с исходным состоянием. Список должен совпадать, кроме явно согласованных изменений запасного HOME. Проверьте пульт, удержание громкости, Wi-Fi, настройки и возврат Home; для ByeByeDPI — связь с backend и состояние VPN. Другие приложения, системные пакеты и сеть ради миграции менять не требуется.

## Будущая смена ключа издателем

Постоянный ключ хранится вне Git, в сборку передаётся через Secrets; необходима независимая защищённая резервная копия ключа и пароля. Смена ключа без переустановки возможна только при поддерживаемой и проверенной цепочке ротации и подходящей версии Android/прошивке. На Android 11 нельзя считать произвольный новый сертификат совместимым. Обновлятор не принимает чужой ключ только по заявлению в JSON.

Основание: [Android: подпись приложений](https://developer.android.com/studio/publish/app-signing), [apksigner](https://developer.android.com/tools/apksigner), [ADB](https://developer.android.com/tools/adb).
