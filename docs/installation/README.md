## Сначала выберите подходящую сборку

**Доступны production-сборки Standard и ByeByeDPI: Milo Home 0.0.3.** Релизы с префиксом `test-` предназначены для отдельного эмулятора или тестового устройства, а не для обновления вашего рабочего лаунчера. Выберите вариант и совместимую подпись; тестовый файл не следует подставлять вместо production APK.

1. Откройте [Releases](https://github.com/anrhangels/milo-home/releases) и прочитайте назначение канала и примечания.
2. Выберите **Milo Home 0.0.3** — текущую общедоступную версию.
3. Выберите Standard или byedpi. Ниже показан Standard: скачайте из одного релиза `MiloHome-standard.apk`, `MiloHome-standard.apk.sha256` и `update.json`. Проверьте размер, SHA-256 и подпись.
4. Если `com.gathin.tvhome` уже установлен, сравните сертификаты и версии **до установки**. Нужны совместимая подпись и больший `versionCode`.

Если подпись установленного приложения отличается, обычное обновление поверх невозможно. Не удаляйте приложение автоматически: сначала подготовьте запасной HOME и согласуйте потерю данных. [Почему и как планировать миграцию](../SIGNING.md).

На всех системах используется официальный [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools). Если подходящий ADB уже установлен и работает, второй экземпляр не нужен. Android Studio для самого ADB не обязателен.

## Подключение к ТВ

Компьютер и ТВ должны находиться в одной доступной друг другу сети. Включите режим разработчика и отладку на ТВ.

- Если в меню есть **беспроводная отладка с сопряжением**, используйте показанные ТВ адрес и порт для `adb pair`, затем отдельный порт подключения для `adb connect`. Они могут отличаться.
- На старых/некоторых телевизорах сетевой ADB использует `5555`, **только если прошивка уже включила прослушивание этого порта**. Галочка USB debugging сама по себе этого не гарантирует.
- Если доступна лишь USB-отладка, воспользуйтесь поддерживаемым изготовителем USB-подключением и [официальным руководством ADB](https://developer.android.com/tools/adb). Порт USB на ТВ не обязательно поддерживает режим устройства.
- При `unauthorized` подтвердите RSA-запрос пультом на экране. При отказе подключения проверьте адрес, порт и режим отладки; не перебирайте порты и не меняйте прошивку.

Во всех командах указывайте точный серийный идентификатор после `-s`, особенно если одновременно открыт эмулятор.

## Проверка APK и старой подписи

Контрольная сумма показывает целостность файла. Она **не заменяет** проверку подписи. В Android SDK Build-Tools есть `apksigner` и `aapt`; в Windows используйте `apksigner.bat` / `aapt.exe`, в Linux/macOS — `apksigner` / `aapt` по полному пути:

```text
apksigner verify --verbose --print-certs MiloHome-standard.apk
aapt dump badging MiloHome-standard.apk
```

Проверьте package `com.gathin.tvhome`, `versionCode`, minSdk, ABI и сертификат. Сверяйте сертификат также с закреплённым значением в [SIGNING](../SIGNING.md), а не только с JSON рядом с APK. Для production используется постоянный сертификат `0eb3e4397a0f1f2c05925c47da6bebeea0e757c41967642af051c774d72b36db`.

Чтобы сравнить с установленным приложением, получите его путь командой `shell pm path com.gathin.tvhome`, скачайте указанный `base.apk` через `adb -s SERIAL pull "ФАКТИЧЕСКИЙ_ПУТЬ" before-MiloHome-standard.apk` и проверьте его тем же `apksigner`. SDK Build-Tools — отдельный компонент, внутри обычного platform-tools его нет. Если проверить подпись самостоятельно трудно, используйте [сценарий с ИИ](../AI-INSTALL.ru.md); не угадывайте совместимость.

APK старой версии и сведения о HOME полезны для восстановления, но **не являются копией частных данных**. У приложения может быть выключен backup. Не обещайте сохранение настроек при смене ключа или удалении.

## Первый запуск и HOME

Сначала запустите приложение из списка установленных и проверьте пультом стрелки, OK, Назад, громкость и переход в настройки. Заводской лаунчер сохраняйте доступным.

Затем выберите Milo Home в настройках приложений по умолчанию / домашнего экрана или в диалоге выбора Home, если прошивка его показывает. Это отдельный шаг: установка APK его не выполняет. При отсутствии такого меню не отключайте старый лаунчер; сначала выясните способ для вашей модели.

Для изученного устройства можно отдельно и осознанно использовать `adb -s SERIAL shell cmd package set-home-activity com.gathin.tvhome/.MainActivity`. Команда меняет HOME; до неё сохраните прежний компонент и проверьте, что он доступен. Некоторые прошивки её не поддерживают. У ИИ нет разрешения выполнять её без согласования плана.

## ByeByeDPI, обновления и возврат

- Сам лаунчер можно использовать без парного backend. Для управления ByeByeDPI нужен [модифицированный backend с согласованной подписью](../BYEBYEDPI.md). Не заменяйте рабочий официальный APK автоматически; его данные и сертификат проверяются отдельно.
- Обновления предлагают Stable/RC и запускают обычный установщик после проверки. Система сохраняет данные при совместимом обновлении; фактическую модель ТВ всё равно нужно проверить.
- Если доступ к GitHub ломает стратегия ByeByeDPI, подберите стратегию отдельно либо вручную решите, выключать ли его на время загрузки. Лаунчер не делает этого сам. [Результаты испытаний](../TESTING.md).
- При проблеме выберите прежний HOME в системных настройках. Если вы меняли его через ADB, восстановите **фактический компонент из before-home.txt**, а не чужое имя пакета.
- Android может отклонить старый APK из-за меньшего кода. [Восстановление](../ROLLBACK.md) использует прежнюю рабочую реализацию с новым, большим кодом и совместимой подписью; не `-d`, удаление или сброс.

## Контроль после установки

Проверьте версию и HOME, сравните список отключённых пакетов с сохранённым, проверьте Wi-Fi и пульт. ByeByeDPI должен оставаться в выбранном пользователем состоянии. Не запускайте debloat заново.
